
# P6 动态生成、视频配字和导出

## 使用

1. 在项目目录运行 .\start.cmd。在图库选图并建立编辑项目，也可打开已有项目中的静态版本。
2. 打开「动态与导出 → 生成与任务」。核对静态锚点和动作描述，再点「提交 1 段视频（可能计费）」。默认 3 秒、720P、无声。页面展示本机状态、平台状态及已返回的计量。
3. 如果关闭页面，可重新启动并打开原项目。暂停只停止本机等待。「继续查询」使用已保存的平台任务 ID。任务下载完成后点「打开结果版本」。
4. 在「视频配字和导出」保存文案，点「预览并导出 MP4」观看或下载。GIF 默认长边 512、12 fps、普通循环，目标体积 5 MiB。可选从开头截取若干秒。超过目标时最多追加三次降尺寸或帧率尝试，仍超出时可下载当前文件或缩短片段。
5. 要修改动作，打开视频版本，回到「生成与任务」修改描述，再明确提交。新版本从同一个静态锚点生成。只改配字时，新的文字版本继续引用原无字视频。
6. 在「项目历史」可恢复视频或静态版本。打开静态锚点可继续做图片选区和静态编辑。PNG 来自静态画面和静态配字。

## 本机测试

在项目目录执行：

~~~powershell
.\start.cmd --check --gpu
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
~~~

环境检查会显示 ffmpeg、ffprobe 路径和版本，h264_libx264 应为 true。32 项测试使用合成素材和模拟请求，覆盖任务恢复、提交不明保护、媒体校验、静态锚点、视频配字、MP4/GIF 导出、动画帧及缓存。

## 实测记录

P0 的既有视频在签名有效期内下载到本机，大小 1,507,700 字节。P6 验收把这段实际视频通过模拟接口交给应用的任务流程，覆盖提交、查询、保存、打开结果、配字及导出。源视频为 960×960、3 秒、30 fps、90 帧、无音轨、H.264。配字后 MP4 的分辨率、时长、帧率和音轨情况与源视频一致。默认 GIF 为 512×512、36 帧、约 3.01 秒，实际普通循环，约 2.29 MiB。同参数二次导出命中缓存。改为 1 MiB 目标时，本机降至 282×282、24 帧，约 0.58 MiB。抽查首帧及第 2 秒，均读到了配字颜色。记录见 runtime/p6-check.json。

本阶段新增云端模型任务 0 个。P0 实际视频用于验证文件兼容性和本机处理，P6 新任务的提交及恢复通过模拟接口验证。动态页上的重新生成按钮会发起新的云端任务。

## 实现和环境

- 首帧使用无字静态锚点。透明像素以白色合成，缩放保留长宽比，极端比例按需白边补齐。静态蒙版和本机文案不随视频请求发送。动态作用域约束参与动作提示词，对应的一次性要求在视频版本成功保存时消耗。
- 无字视频经本机 ffprobe 校验后作为资产保存。任务和费用记录复用现有 SQLite 数据结构，数据库结构版本为 4。导出按实际像素尺寸生成透明文字层，FFmpeg 用参数列表接收文件。MP4 为 H.264/yuv420p 并支持快速开始，GIF 使用两遍调色板流程。编码失败时可从原视频再次导出。
- 优先使用项目内 runtime/ffmpeg/bin 的 ffmpeg.exe 和 ffprobe.exe，否则查找 PATH。当前项目实际安装的 ffmpeg 构建为 N-92722-gf22fcd4483，ffprobe 为 2023-02-13-git-2296078397-essentials_build。二进制通过 npm 上两个 Windows x64 安装包的发布校验值验证，保存在项目运行目录。系统 PATH 保留原配置。
- 重新安装可从 [FFmpeg 下载页](https://ffmpeg.org/download.html) 选 Windows 构建，将两个程序放入上述 bin 目录，再用环境检查和本地测试验证 libx264。视频请求字段参照 [阿里云万相首帧图生视频接口](https://www.alibabacloud.com/help/en/model-studio/legacy-image-to-video-api-reference)。
